# 1.0.1 便携数据与旧数据导入

程序默认使用安装根的 `data/machines/<本机摘要>/`，其下分别是 `native`、`bridge`、`history` 和 `updates`。本机摘要目录用于区分不同电脑，完整校验值另存；不是网络账号或认证密钥。默认 CSV 是安装根的 `log`。源码与测试必须明确提供 `--data-dir`，对应独立数据根，不读取旧用户默认 profile。

同一台电脑移动整个安装文件夹时，默认日志路径随安装位置更新，自选外部日志目录保持原值。配对文件使用相对路径。同一台电脑同时只运行一个安装；复制前先退出，保留 SQLite 及其伴随文件的完整状态。复制到另一台电脑不会自动沿用旧机身份或配对，请在新电脑重新配对。

旧版目录不会在启动时自动搬迁。以下工具只导入原始测量、CSV 和本地设置，不导入设备令牌、配对文件、会话或旧发布者身份。

旧版更新器在同机原地升级并传入原 `--data-dir` 时，沿用原目录布局与配对，不必使用此工具。此处的导入流程用于明确选择的新安装副本；跨电脑应重新配对。

先正常退出旧程序，并准备**尚未启动过的新安装目录**。旧目录可以保留备份。请把示例路径改成自己实际的路径，避免指向其他实验的文件。

先只检查，不复制：

```powershell
& '.\Qchip TEC.exe' --import-legacy `
  --native-source 'D:\OldTEC\native-profile' `
  --history-source 'D:\OldTEC\history-store' `
  --csv-source 'D:\OldTEC\csv' `
  --install-dir 'D:\NewTEC' `
  --report '.\import-inspection.json'
```

`--native-source` 内应有 `.runtime/settings.json` 或 `settings.json`。`--history-source` 内应有 `tec-local-log-v1.sqlite3`。`--csv-source` 可省略；指定后仅复制该目录下的 `.csv` 文件，不递归扫描其他目录。检查不会创建目标数据目录；报告仅写到你明确指定的新文件。

核对报告后，在同一命令中加 `--confirm`，并给报告另选一个尚不存在的文件名，例如 `import-result.json`。这一步使用 SQLite backup API 创建一致副本，保留原 CSV 字节；原目录中的文件不移动、不删除。已有目标数据或日志目录会被拒绝，不静默覆盖。复制失败时保留本次 staging 以供核对，原数据不受影响。

导入后日志保持关闭，超频关闭，不连接仪器；旧自选 CSV 保存目录仍保留。CSV 副本另存于新安装的 `log`。先在设置中核对实际日志目录，再决定是否开启记录。新历史保留原测量和毫秒时间，但使用新的发布者身份；云端配对需要重新完成，不复用旧机令牌。

若新版已经启动并创建过目标数据目录，工具会安全拒绝。请选择另一个全新解压、尚未启动的安装目录进行导入，不要删除已有实验数据来绕过检查。
